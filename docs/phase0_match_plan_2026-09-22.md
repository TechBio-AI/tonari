## 2. 手順

1. 難病情報センター 7 ページを取得（1 秒 1 回）→ `348 件 × {告示番号, ふりがな, 病名, 解説URL}`
2. 小児慢性 群ページ 14（+不明分）を取得（1 秒 1 回）→ `N 件 × {群ID, 病名, 個別ページURL}`
3. Orphanet は §1-3 の既存結果を読み込む（取得なし）
4. 951 件 × 3 出典で照合、3 段階判定
5. 出力を 2 つ書く
6. `docs/kb_issues_2026-08-29.md` に「orpha_code 誤り 44 件」を追記

取得は生 HTML を `data/disease_overviews/_raw/` に日付つきで保存し、再実行時は再取得しない（サーバに優しく、結果を再現可能にする）。

### 2-1. 照合の正規化（機械。ここに書いた以外のことはしない）

両側の病名に同じ処理をかける:

1. NFKC 正規化（全角英数 → 半角、全角記号 → 半角）
2. 小児慢性の病名の先頭にある連番（`12. `）を落とす
3. 空白・`・`・`／`・`-`・`‐`・`−`・`（）`『』「」 の記号を落とす
4. 英字は小文字化

さらに **括弧の中身を落とした版**も作り、両方で突き合わせる（`潰瘍性大腸炎（難治型）` ⇔ `潰瘍性大腸炎`）。
照合の対象は、我々側は `disease` + `alternate_names`、相手側は掲載病名（小児慢性は括弧内の英語表記も別名として扱う）。

### 2-2. 3 段階の判定

| 判定 | 条件 |
|---|---|
| **完全一致** | 正規化後（括弧つきのまま）に文字列が同一 |
| **部分一致** | ①別名どうしの一致 ②括弧の中身を落とせば一致 ③一方が他方を含み、短い側が長い側の 50% 以上の長さ ④既知一致（§1-4）と食い違う ⑤同じ相手に 2 件以上がぶつかる |
| **なし** | 上のどれでもない |

**推測での紐付けはしない。**「近そう」は全て部分一致に落とし、ファウンダーの ○× を待つ。

## 4. 判断が要る点

### 4-1. ★ フェーズ1 の「10 並列」と「1 秒に 1 回」は両立しない

フェーズ1 が 951 疾患 × 3 出典の本文取得なら、最大 2,853 リクエスト。**1 秒 1 回を守ると純粋な取得だけで約 48 分**、10 並列にしても**合計レートが 1 req/sec なら所要時間は変わらない**（並列は待ち時間を増やすだけ）。

どちらの意味かの確認をしたい:
- **(A)** 1 秒 1 回は 3 ドメイン合計の上限。10 並列は「抽出（本文の読み取り）を 10 分割して進める」の意味で、取得は直列 ← **推奨**
- **(B)** 1 秒 1 回はドメインごと。3 ドメイン同時で 3 req/sec まで
- **(C)** 10 並列 = 10 req/sec

(A) を前提に、フェーズ1 は「取得は直列でまとめて先に済ませ、保存した HTML に対して 10 分割で抽出する」形を提案する。

### 4-2. 難病情報センター側の粒度が我々と違う

告示番号順索引は**指定難病 348 件**しかない。我々の 951 件の多くは指定難病ではない（小児慢性のみ、どちらでもない）。
また我々の病名は告示名より細かいことがある（例「潰瘍性大腸炎（難治型）」「特発性拡張型心筋症（小児）」）。
→ 部分一致が相当数出る見込み。**件数は照合してみないと不明。** 実測値は報告に入れる。

### 4-3. 小児慢性の 15・16 群

§1-2 のとおり不明。実行時に確認する。見つからなければ「索引に無い」と記録し、推測で URL を作らない。この判断でよいか。

### 4-4. Orphanet の URL は `/ja/` か `/en/` か

`https://www.orpha.net/ja/disease/detail/{番号}` と `/en/` はどちらも HTTP 200 を返すが、**ボット検査ページが返るため中身を機械確認できない**（前回調査済み）。
日本語話者向けなので `/ja/` を推すが、日本語コンテンツが実際にあるかは**不明**。
- **(A)** `/ja/` を使う ← 推奨
- **(B)** `/en/` を使い、リンク文言に「英語」と添える
- **(C)** 保留（フェーズ1 で人が 1 件開いて確かめてから決める）

### 4-5. `data/disease_overviews/` を新設してよいか

「data/ の原本に触れない」は守る（既存ファイルは 1 バイトも変更しない）。新しいディレクトリ `data/disease_overviews/` を作り、そこに照合表と取得した生 HTML を置く。この置き場でよいか。
別案: 生 HTML は `data/` に置かず作業用ディレクトリに留め、`_match_table.json` だけ `data/` に置く。

### 4-6. フェーズ1 の 10 分割案（idx 範囲）
