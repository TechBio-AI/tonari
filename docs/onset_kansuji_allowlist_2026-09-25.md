# onset の漢数字規則：許容してよい語の候補（機械抽出）

2026-09-25 生成。**候補一覧です。判定はしていません。** ファウンダーの承認後に
`docs/disease_overview_phase1_task.md` と `scripts/portal/validate_overview.py` へ反映します（フェーズ1b）。

## 1. 何のための一覧か

onset の規則は「`text` / `evidence` に数字（半角・全角・漢数字）を含めない」（2026-09-25 ファウンダー指示）。
目的は、有病率・患者数の数値が onset に紛れ込むのを防ぐことです。
ところが漢数字を 1 文字でも見ると落とすため、**数を表さない「四肢」「一般」「一部」なども巻き添えで落ちます。**
その巻き添えだけを救うための許容一覧をつくります。

## 2. 出し方（機械。判断は入れていない）

- 読んだのは `.cache/disease_sources/pages/nanbyou_entry_*.html` の **163 枚**だけ。Web 取得はしていません。
- 対象の節は「どのような人に多いのですか」（onset の出所）**156 個**。ほかの節も語の候補集めには使いました。
- **形態素解析は使っていません**（2026-09-13 ファウンダー判定）。代わりに、漢数字 1 文字ごとに
  「その字から始まる 2 文字・3 文字の漢字列」と「その字で終わる 2 文字の漢字列」を切り出しました。
  語の切れ目は見ていないので、**切り出しに失敗した断片が混じります**（`二指`（十二指腸の一部）、`設一`、`医一` など）。
- 「数の文脈で使われるか」は**直前 3 文字に算用数字があるか**で機械的に見ています（`10万人` → `万人`）。
- 生データ: `data/disease_overviews/_onset_kansuji_scan.json`、生成: `scripts/portal/scan_onset_kansuji.py`

## 6. 参考：本文には出るが onset の節には出ていない語

## 7. 判断が要る点

1. **表A の 13 語で足りるか。** いまの保存本文（163 枚）では足ります。
   フェーズ1b で残り 788 疾患の本文を取ると、新しい語が出てくるはずです。
   そのときは一覧を更新するのか、それとも「今回の 13 語で固定し、落ちたものは onset を null にする」のか。
2. **`四徴` `三好` `同一` `一家` `二次` をどうするか。** `四徴症`（ファロー四徴症）`三好型` は病名・病型の一部、
   `同一家系` は家族歴の記述です。数を表してはいませんが、数える意味は残っています。
3. **表B の扱い。** 許容しない、で問題ないか。`万一` だけは慣用句ですが、onset の節には出ていません。
4. **1b での実装方法。** `validate_overview.py` は「漢数字の 1 文字ごとに、その位置を覆う許容語があるか」で
   判定する形にします。`task.md` にも同じ一覧を書きます。この形でよいか。
