# 統計の秘匿の共通ルール

作成: 2026-10-02 Claude Code（ファウンダー指示）
対象: 会員エリアで人数を出すすべての集計。いまあるのは次の 2 つ
- 道のり調査の会ごとの集計 `public.journey_summary`（`supabase/migrations/20261010_journey_survey.sql`）
- 世話人向けダッシュボード `public.group_dashboard`（`supabase/migrations/20261012_group_dashboard.sql`。患者会テナント担当）

この文書と migration の原本が食い違ったときは、原本を正として、この文書を直す。

## 1. しきい値は 10（NDB 準拠）

- 人数が **10 未満** の区分（セル・行）は数を出さず、「**10未満**」と表示する
- **0 も含む**。0 人の区分も「10未満」にする（0 と 1〜9 を見分けられないようにする）
- 根拠: NDB オープンデータの FAQ（厚生労働省「NDBオープンデータ FAQ（第10回更新版）」No.006 https://www.mhlw.go.jp/content/12400000/001568663.pdf）は、「集計単位が10未満の場合は『-（ハイフン）』で表示」するとしている
- NDB との違い:
  - 表示は「-」ではなく「10未満」
  - NDB は、伏せた項目が 1 つだけで、かつその値が 0 でないときに補完秘匿をかける。このルールでは 0 も伏せる区分に含めるので、伏せた区分が 1 つなら、その値が 0 でも補完秘匿をかける（NDB より慎重な側）
  - NDB は、マスクの仕様は回ごとに変わるとし、詳細は各回の解説編「最小集計単位の原則」を見るよう案内している。解説編の原文は確認していない（**不明**）

## 2. 補完秘匿

- 同じ表の同じ列（ダッシュボードでは同じ section）で、伏せた区分が **ちょうど 1 つ** なら、伏せていない区分のうち **最小のもの** も伏せる（同じ数なら選択肢の並びが先のもの）
- 理由: 総数や他の区分の合計がわかっていると、伏せた 1 つを引き算で戻せるため
- 実装:
  - `journey_summary` の h3（単一選択の設問の「全体」の列）
  - `group_dashboard` の h2（「journey_summary の h3 と同じ補完秘匿」と原本に書いてある）

## 3. 実数で出してよいもの

伏せずに実数で出すのは、世話人向けダッシュボードの次の 3 つだけ（ファウンダー指示。`group_dashboard`）。
- 在籍会員数（退会していない会員）
- 世話人数（在籍している世話人）
- 未審査の入会申請数

これ以外の人数（年代・性別・地方・登録者の種別・道のり調査の回答など）は、すべて 1 と 2 のルールで伏せる。

- 公開の参加状況 `public_disease_participation` の `research_contact`（20261025）は、研究の案内の**いまの版**（`consent_current_version('research_contact')`）に同意して取り消していない人だけを数える（案件の可視範囲と同じ規則）。そのため**版が上がると、同意し直すまでの間は一時的に数が減る**（減った分を「辞めた人」と読まない）。

## 4. 道のり調査だけの追加ルール（`journey_summary`）

- **前月までの回答だけを数える**。数えるのは `answered_month` が今月の 1 日（日本時間）より前の回答。その月の回答は翌月から数に入る。会員が、知人の回答の前後で集計を見比べて、その人の回答を割り出すことを難しくするため
- **単純集計と、性別との 2 軸だけ**。設問ごとの単純集計と、性別（男性・女性・答えない）とのクロス集計だけを返す。ほかの掛け合わせは返さない。性別の設問そのものは性別と掛け合わせない
- 以下も 20261010 の実装に入っている（ファウンダー採用 2026-10-02。詳しくは `docs/journey_survey_items.md`「集計の決まり」）:
  - 総数が 10 未満なら、集計そのものを返さない（総数の行も含めて 0 行）
  - 性別ごとのセルは、同じ選択肢の行で 1 つでも 10 未満なら、3 つとも伏せる。ただし「答えない」と回答した人が 1 人もいなければ、「答えない」の列はこの判定に入れない
  - 「全体」のセルを伏せた選択肢は、性別ごとのセルも伏せる
  - 単一選択の設問で、性別ごとのセルを伏せた選択肢がちょうど 1 つなら、「全体」の数が次に小さい選択肢の性別ごとのセルも伏せる
  - 複数選択の設問（最初に気づいた症状）には補完秘匿をかけない（区分の合計が総数にならず、引き算で戻せないため）
- 集計の関数は、本人と回答の対応表（`journey_links`）を読まず、user_id も返さない

## 5. しきい値の置き場

- しきい値の正は `public.stats_threshold()`（10 を返す）。患者会テナント担当が `20261012_group_dashboard.sql` で作った（PUBLIC・anon・authenticated は実行不可。集計の関数の中から、所有者の権限で使うだけ）
- 使っている関数:
  - `group_dashboard`（20261012。20261016 で差し替え後も同じ）
  - `journey_summary`（`20261018_journey_summary_threshold.sql` で差し替えた。20261010 では 10 を直書きしていた 3 か所〔総数の判定 1・セルの判定 2〕を `v_t := public.stats_threshold()` にした。ほかは 20261010 と同じ）
  - `journey_summary(会, 病気)`（`20261028_journey_generalize.sql` で病気ごとに動く形にした。集計と秘匿は病気ごと・会ごと。秘匿ルールは 20261018 と同じ）
- `stats_threshold()` が 10 を返す限り、`journey_summary` の結果は 20261010 と変わらない。確認は `scripts/portal/verify_journey.sql` を変えずにもう一度流す
- 表示の文字「10未満」は、どちらの関数も文字として直書きしている。しきい値を変えるときは、この文字と、画面・印刷の注記（`lib/portal/journey-survey.ts` の `JOURNEY_PRINT_NOTE`、`app/demo/community/[slug]/_lib/dashboard.ts` の `DASHBOARD_NOTE` など）も一緒に直す
