## 4. 判断が要る点

### 4-1. ★ 出典が無いまま 940 疾患の説明を公開してよいか

CLAUDE.md の公開面第 1 原則は「出典なき情報は存在させない」。
`docs/survey_kb_health_2026-08-29.md` の実測では、知識ファイルの**出典フィールド 0 件・HPO ID 0 件・URL 0 件**、検証可能な出典を持つ疾患は **0 件**。第 3 批次 926 件は LLM 生成の可能性が高いと記録されている。

今回出す `description` / `symptoms` / `diagnosis` / `treatment` は、**すべてこの出典なしデータ**。
指示は「951 件すべてに中身を出す」なので、そのとおり実装する準備はできている。ただしこれは原則の例外にあたるため、明示の承認が要る。

選べる形:
- **(A)** そのまま出す。冒頭の固定文（「当サイトによる要約です」）で当サイト作成物であることを示す ← 指示どおり
- **(B)** (A) に加え、概要層に「この説明にはまだ出典を付けていません」の 1 行を足す ← **推奨**
- **(C)** 出典を付けるまで出さない（今回を見送る）

### 4-2. Orphanet リンクの範囲
- **(A)** 761 件すべてにリンク（44 件が別疾患のページに飛ぶ）
- **(B)** 717 件にリンク、44 件は出さない ← **推奨**
- **(C)** 完全一致 549 件だけ

### 4-3. 小児慢性特定疾病情報センター
- **(A)** クエリ無しで検索ページへリンクし「病名で検索できます」と添える ← **推奨**
- **(B)** リンクしない（深リンクできないため）

### 4-4. 治療の出し方
- **(A)** §1-7 のフィルタ（688 疾患に表示、263 疾患は見出しごと非表示、残留 113 件は要確認リストを出す） ← **推奨**
- **(B)** `treatment` をそのまま出す（527 疾患に薬剤名が出る。11 件で決めた方針と矛盾）
- **(C)** 概要層に治療を出さない（出典付きで書き直すまで待つ）

### 4-5. 既存の約束を 2 つ書き換えることになる
`app/demo/__tests__/wording.test.tsx` の以下 2 件は、今回の指示と正面から衝突する。指示が新しいので書き換える前提だが、意図の確認をしたい。
- 「病気のページ（準備中）には説明文と ORPHA 番号が出ない」← 説明文を出すので書き換え（ORPHA 番号は引き続き出さない）
- 「日本語の病名が無い病気のページに、説明と別名が出て、ORPHA 番号は出ない」← 同上

### 4-6. 固定文の言い回し
指定の文「この説明は当サイトによる要約です。」は、実際には**継承した知識ファイルの文をそのまま出す**もので、当サイトが要約したわけではない。
外部の出典を騙らない点で問題は無いと判断しているが、正確に言うなら「この説明は当サイトが用意したものです。」。指定どおりで進めてよいか。
